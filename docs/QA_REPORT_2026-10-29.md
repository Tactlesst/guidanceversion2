## How real data was protected

Mutable tests shadow their dependent tables using connection-local temporary tables, including users, notifications, audit records and email outboxes. Concurrency uses a uniquely named test-owned database, with cleanup restricted to that database. Mail delivery is fake; no additional real test email was sent.

Live HTTP checks used the supplied accounts for sign-in, read-only pages and empty report exports. Normal sign-in/export audit records were created. They did not submit real student forms, bookings, approval decisions or conversions.

No extra real SMTP delivery, destructive live restore, public-host deployment, external penetration scan or production-scale load test was performed. The two-process booking tests are concurrency checks, not a large load test.
